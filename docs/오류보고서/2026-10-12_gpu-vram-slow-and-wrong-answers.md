# sLLM 답변이 18~48초 걸리고 일부 답이 틀림 (VRAM 부족 + 학사일정 청킹 + 근거 기준값)

- **발생 시각**: 2026-10-12
- **위치**: `ask-campus` 서버 (`llm.py`, `index.py`, `rag.py`, `ingest/sources.py`), 노트북 GPU RTX 5060 Laptop 8GB
- **상태**: 해결됨 (일부 한계는 남음)

## 증상

`scripts/smoke_test.py` 첫 실행 결과:

- 응답 시간 18,383 / 20,480 / 47,904 / 33,854ms (짧은 답은 1,418~2,134ms). 목표는 평균 5초(PER-001).
- "등록금 환불 2/3선 언제야?" → "11월 18일"이라고 답함. 수집한 학사일정은 `등록금 환불 2/3선: 2026.10.30`.
- 자료에 없는 "편입생 전공 학점 인정 몇 학점까지야?"에 근거 없음이 아니라 관련 없는 공지(전과·재입학)를 엮어 답함.
- 일부 답이 "[자료] (1) …"로 시작 (프롬프트 형식을 따라 씀).
- 마지막 질문은 60초 시간 초과.

## 원인 조사

1. **느림:** `nvidia-smi` → 사용 7,841 / 8,151MiB. 에뮬레이터(qemu)가 GPU를 같이 쓰고 있었고, 임베딩 모델이 fp32로 올라가 있었다. 짧은 답은 빠르고 긴 답만 급격히 느려지는 모양이 VRAM이 공유 메모리로 넘친 것과 맞았다 (가설). 고친 뒤 대부분 1~3초로 줄어 가설과 일치.
2. **2/3선 오답:** 학사일정을 **월별로 묶어** 청크를 만들었더니, 10월 청크가 상위 3개에 들지 못하고 9월·11월 청크만 근거로 들어갔다. 모델이 그 안의 다른 날짜를 답으로 씀.
3. **근거 없음 실패:** 근거 기준값이 0.45였다. 질문 10개로 점수를 재 보니 답이 있는 질문 상위 점수 0.629~0.817, 없는 질문 0.472~0.607. 0.45는 너무 낮았다.
4. **형식 따라 쓰기:** 근거를 user 메시지에 `[자료] (1) …`로 넣은 것이 원인.

## 근본 원인

- 8GB GPU를 sLLM(bf16 약 4.2GB) + 임베딩(fp32) + 에뮬레이터가 함께 써서 VRAM이 부족했다.
- 학사일정 청크 단위가 너무 커서 검색이 빗나갔다.
- 근거 기준값이 측정 없이 정한 값이었다.

## 해결 방법

| 조치 | 파일 |
|---|---|
| 임베딩 모델을 fp16으로 올림 (`model_kwargs={"dtype": torch.float16}`) | `index.py` |
| 에뮬레이터를 `-gpu swiftshader_indirect`(소프트웨어 렌더링)로 실행. 실제 시연은 별도 폰이라 해당 없음 | 실행 방법 (README) |
| 학사일정을 일정 1건 = 청크 1개로 (66개) | `ingest/sources.py` |
| 근거 기준값 0.45 → 0.60 (환경 변수 `ASK_MIN_SCORE`로 조정 가능) | `config.py` |
| 근거를 system 메시지로 옮기고, `[자료]`·`■`로 시작하는 줄은 지움. 근거 없음 표현을 여러 문구로 판별 | `llm.py`, `rag.py` |
| 답변 1~4문장, 맺음말 금지, 최대 200토큰 | `llm.py` |
| 서버 시작 때 짧은 생성을 한 번 해 첫 질문 지연(약 18초)을 미리 치름 | `llm.py` `warm_up()` |
| 출처는 최고 점수와 0.04 이내인 근거만 표시 | `rag.py` |

결과 (같은 smoke test): 답이 있는 질문 1,197~2,919ms, 2/3선 "10월 30일" 정답, 자료에 없는 질문 4개 모두 근거 없음 + 답변 대기 등록.
