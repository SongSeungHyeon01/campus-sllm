# 다른 표현의 "근거 없음" 답이 답변 대기에 안 올라감 + 빈 연락처·맺음말 노출

- **발생 시각**: 2026-11-10
- **위치**: ask-campus/src/server/llm.py (`is_not_found`, `_clean`), scripts/model_compare.py로 발견
- **상태**: 해결됨

## 증상
sLLM 후보 비교(scripts/model_compare.py, 질문 19개) 중 확인:

1. Midm 2.0 Mini가 "2학기 기말고사 시험 장소 어디야?"에 `제 2학기 기말고사 시험 장소는 제공되지 않았습니다.`라고 답함.
   이 답은 answer_type `문서`로 처리됐고, 답변 대기에 등록되지 않음.
2. Kanana-2 3B(4bit)는 "기숙사 신청 언제 해?"에 `해당 정보는 존재하지 않습니다. … 감사합니다. </p>`라고 답함. 이 답도 `문서`로 처리됨.
3. 지금 쓰는 Kanana 1.5는 "국악 동아리 있어?" 답에 아래 줄을 그대로 붙임:
   - 자료의 빈 칸 `연락처: 010-`
   - `궁금한 점이 있으면 말씀해 주세요!` (SYSTEM 규칙 4가 금지한 맺음말)
   - 이 현상은 중간현황보고서에도 남은 문제로 적혀 있었음.

## 원인 조사
- `is_not_found`는 정해 둔 문구 목록으로만 판정함. 목록에는 "찾을 수 없", "자료에 없", "나와 있지 않" 등이 있었음.
  "제공되지 않", "존재하지 않"은 목록에 없었음.
- 지금 모델(Kanana 1.5)은 거의 항상 규칙 2대로 "해당 정보를 찾을 수 없습니다"라고 답해서 그동안 드러나지 않았음. 모델을 바꾸면 바로 드러나는 문제임.
- 원래 `_clean`은 `[자료]`·`■`로 시작하는 줄만 지웠음. 그래서 빈 항목, 맺음말, HTML 태그는 걸러지지 않았음.

## 근본 원인
- 근거없음 판정이 모델의 말투에 의존함.
- 후처리가 모델이 따라 쓰는 자료 형식 일부만 다루고 있었음.

## 해결 방법
llm.py를 아래처럼 고침.
- `_NOT_FOUND_HINTS`에 추가: "제공되지 않", "존재하지 않", "언급되어 있지 않", "포함되어 있지 않", "정보가 없"
- `_clean`에 추가:
  - `연락처: 010-`처럼 값이 비었거나 번호 앞자리만 남은 `항목: ` 줄 삭제
  - 40자 이하 줄 중 맺음말 패턴("궁금한 점", "문의 주세요", "감사합니다" 등)이 있으면 삭제
  - HTML 태그 삭제

검증:
- 네 번의 비교에서 기록된 모델 원문에 새 규칙을 적용함.
  - Midm·Kanana-2의 위 답이 근거없음으로 바뀜.
  - 정상 답 중 근거없음으로 잘못 바뀐 것은 없음.
- 정상 문장 대조: `연락처: 010-1234-5678`, `회원수: 34명`, `진행하지 않으며` 문장은 그대로 남음.
- Kanana 1.5로 다시 실행: 답 있는 질문 12/12, 자료에 없는 질문 4/4.
  동아리 답은 `… "한맥"이 있습니다. / 소재: … / 지도교수: … / 회원수: 34명`로 나옴.
- time_test.py 10/10 통과.
- e2e_test.py는 서버를 띄워야 해서 이번에는 실행하지 않음.

## 재발 방지
- 모델을 바꾸거나 프롬프트를 고치면 scripts/model_compare.py를 먼저 돌림.
- 이때 `[trap]`·`[none]` 문항의 answer_type을 확인함.
- 평가 질문 80개 세트를 만들 때 "자료에 일부만 있는 질문"을 따로 넣음.
