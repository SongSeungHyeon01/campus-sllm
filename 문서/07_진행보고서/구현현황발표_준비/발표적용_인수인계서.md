## 1. 해커톤에서 가져올 것, 버릴 것

해커톤은 사업 피칭이고 우리는 캡스톤 구현현황 발표예요. 그래서 그대로 가져오지 않고 아래처럼 바꿔서 적용해요.

| 해커톤 교훈 | 우리 발표에 적용 | 비고 |
|---|---|---|
| 문제를 한 문장으로 다시 정의한 팀이 칭찬받음 ("총무의 노동") | "학교 정보는 **있는데** 못 찾는다"를 키 카피로 씀 (1차 설문: 포털 검색·메뉴 불편 78%) | 중간발표에는 이 문장이 없음 |
| 자체 실측치가 가장 강한 근거였음 (167개 중 165개 등) | **평가 질문셋 정확도**를 반드시 숫자로 제시 | 중간발표 최대 약점이 "아직 못 쟀다" |
| 단계형 AI 검증 + 사람 최종 승인 구조가 호평 | 우리 구조가 이미 이 형태임 → 다이어그램 1장으로 보여줌 (아래 2절) | 강점인데 지금은 흩어져 설명됨 |
| "ChatGPT로 되잖아?"에 약하게 답한 팀은 감점 | 차별점 3가지를 슬라이드에 먼저 넣음 (QnA_대비.md Q1) | |
| "땀 냄새 나는 검증" 요구 | 버스 오답(10:15 vs 08:00), 근거없음 문구 누락(11/10) 사례를 **원인 → 수정 → 재시험 수치**로 | 이미 소재가 있음 |
| 데이터 출처·신뢰성·최신성 질문이 반복됨 | 수집 출처·수집일·갱신 방식을 표 1장으로 | 10/12 수집본 그대로인 게 약점 |
| 개인정보 질문에 "문제없을 것 같다"는 감점 | "저장하지 않는 것 / 가리는 것 / 지우는 시점"을 구체적으로 | 이름 가리기 미구현 → 발표 전 구현 권장 |
| 한계를 먼저 밝힌 팀(반걸음)은 신뢰를 얻음 | 지금처럼 "남은 문제" 장 유지 | 중간발표에서 이미 잘함 |
| 장면으로 시작하는 시연 | "시험 기간 신입생이 '기말고사 언제야?'를 묻는 장면"으로 시연 영상 시작 | |
| 시연 영상 구간 넘기기에서 시간 손실 | 영상 구간별 타임스탬프 표를 미리 만들어 둠 | |
| 질의응답 답변이 길면 중간에 끊김 | 답변은 결론 1문장 + 근거 1문장, 30초 이내 | |
| 사업 모델·시장 규모 | **해당 없음.** 대신 "운영 지속성" 질문을 대비 (조교 부담, 서버, 갱신) | |

## 2. 우리 프로젝트의 검증 파이프라인 (발표용 다이어그램 소재)

해커톤에서 가장 좋은 평가를 받은 장면은 "AI가 틀리면 어떻게 막나"를 단계로 보여준 부분이었어요. 우리 시스템은 이미 아래 단계를 갖추고 있어요.

```
질문
 → ① 검색 (KURE-v1 + Chroma) — 유사도 기준값 0.60 미만이면 답하지 않음
 → ② 정해진 계산은 코드가 처리 — 통학버스 다음 차 (sLLM 사용 안 함, 0.04초)
 → ③ sLLM 답변 (Kanana 1.5 2.1B) — 근거 자료만 사용하도록 지시
 → ④ 후처리 — "근거 없음" 표현 판정, 빈 항목·맺음말·HTML 제거
 → ⑤ 출처 최대 3개 + 원문 보기 + 홈페이지 메뉴 위치 표시
 → 근거 없음이면 ⑥ 답변 대기 자동 등록 → 조교 답변 → FAQ 즉시 반영
```

- 강조할 메시지: **"모르면 지어내지 않고, 사람이 답한 내용이 다시 근거가 된다."**
- ②와 ④는 실제 오류를 겪고 추가한 단계예요. 이 내용이 "땀 냄새" 근거가 돼요.
