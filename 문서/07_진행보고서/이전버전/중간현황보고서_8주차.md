### 설계에서 크게 바뀐 점

교수님 피드백과 팀 검토를 거치며 다음과 같이 정리했습니다.

- **학과 조교의 역할:** 학생과 같은 사용자에서 **중간 관리자(답변 담당자)** 로 바꿨습니다. 학과장·교무처·학생처는 시스템을 직접 쓰지 않으므로 액터가 아니라 시스템 밖의 '정보 제공 조직'으로 표시했습니다.
- **모르는 질문 처리:** 기록만 하던 방식에서, 자동으로 답변 대기에 등록 → 조교 답변 → FAQ DB 즉시 반영 → 질문한 기기에 익명 알림으로 이어지게 했습니다.
- **조교 로그인:** 비밀번호 대신 이메일 6자리 인증 코드로 정했습니다. 관리자가 이메일을 등록·삭제해 권한을 관리하고, 매일 오전 9시에 답변 대기 요약 메일을 보냅니다.
- **앱 구성:** 카테고리·답변 상세 화면을 없애고 채팅 화면 중심으로 줄였습니다.

## 6. 발견한 문제

### 6.1 개발 중 해결한 문제

| 문제 | 원인 | 해결 |
|---|---|---|
| 서버가 시작되지 않음 | 최신 transformers 5.x가 Kanana 모델 설정을 거부 | 4.x 버전으로 고정 |
| 답변이 18~48초 걸림 | GPU 메모리(8GB) 부족 | 임베딩 모델을 절반 정밀도(fp16)로 올리고, 에뮬레이터 GPU 사용을 끔 |
| 등록금 환불 일정 오답 | 학사일정을 월별로 묶어 검색이 빗나감 | 일정 하나를 청크 하나로 분리 |
| 자료에 없는 내용을 지어냄 | 근거 기준값이 낮음(0.45) | 0.60으로 올림. 질문 10개로 정한 임시값 |
| 조교 답변 등록 후 500 오류 | Chroma 첫 입력 직후 검색 오류 | FAQ·답변 대기를 SQLite로 이동 |
| "가장 빠른 버스"에 10:15로 답함 (08:00이 맞음) | 시간표 조각 일부만 검색, 현재 시각 미전달, 모델의 시간 비교 한계 | 시간표 조회는 코드가 계산 |

### 6.2 아직 남은 문제 (이번 재시험에서 확인)

| 문제 | 내용 | 대응 계획 |
|---|---|---|
| **구어체 질문을 놓침** | "학교 동아리 뭐있냐 지금 신청할만한거 아산"이 근거 없음 처리됨. 동아리 자료가 있는데도 공모전 공지가 1위로 나오고 점수도 0.552로 기준 미만 | 평가 질문셋에 구어체를 넣어 측정, 리랭커 적용, 기준값 재조정 |
| **이미 지난 일정을 그대로 안내** | "수강정정 언제까지야?"에 9월 폐강 정정 기간을 답함. 지났다는 안내가 없음 | 날짜를 코드로 비교해 지난 일정임을 표시 |
| **데이터가 갱신되지 않음** | 10/12 수집본 그대로. 자동 재수집이 없어 공지 3시간 내 반영(PER-008) 미충족 | 스케줄러 구현 |
| **불필요한 정보가 답에 섞임** | 동아리 답변에 학교 페이지의 빈 칸 "연락처: 010-"이 나옴. 완전한 전화번호는 수집 자료에 없음을 확인 | 수집 단계에서 연락처 칸 제거 |
| **이름을 가리지 않음** | 저장 전 가리기가 전화번호·학번 형태만 처리. 요구사항(FR-028)과 조교 웹 안내문은 이름까지로 되어 있음 | 이름 처리 방법 검토 후 구현 |
| **30일 만료 미동작** | 만료일은 저장하지만 처리하는 작업이 없음 (AVL-008) | 스케줄러 구현 때 함께 처리 |
| **평일·주말 외 시간표** | 방학 기간을 몰라 평일은 학기 중 시간표로 답함 | 학사일정에서 방학 기간 판정 |

프로토타입은 공개 모델과 오픈소스, 팀 노트북으로 만들어 구동에 유료 서비스를 쓰지 않았습니다. 앞으로의 예상 비용은 최소 0원, 권장 약 3~4만 원(파인튜닝 기간 Colab Pro), 넉넉히 잡아 10만 원 이내입니다. 금액은 모델 선정·예산 검토 기준의 추정치입니다.

| Android 전용이라 iPhone 사용자는 쓸 수 없음 | 2차 설문 Q4로 비율 확인 후 범위 판단 |
| 노트북 한 대가 서버라 항상 켜 둘 수 없음 | 시범 운영 기간을 정해 구동. 외부 접속은 무료 터널 검토 |
| 메일 발송 계정 미정 | 발송 전용 계정을 먼저 만들어 시험 |
| 조교 협조 여부 미확정 | 인터뷰에서 참여 요청. 어려우면 팀원이 조교 역할로 시연 |

## 9. 결정이 필요한 사항

1. sLLM·임베딩 모델 최종 확정 (평가 질문셋 비교 후)
2. 메일 발송 계정 (Gmail 앱 비밀번호 또는 학교 메일 SMTP)
3. 통학버스 시간 조회를 코드로 처리하는 방식을 요구사항에 반영할지
4. 학교 FAQ(로그인 필요) 활용 허락 경로 (조교 인터뷰로 확인)
