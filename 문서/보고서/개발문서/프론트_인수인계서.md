## 3. git 규칙

1. master에 직접 푸시하지 않습니다. 브랜치 → 커밋 → PR로 올립니다. 병합은 사용자가 시킬 때만 합니다.
2. 커밋 메시지는 `<타입>: <요약>` 형식입니다 (feat·fix·docs·refactor·test·chore).
3. **`Co-Authored-By: Claude`나 "Generated with Claude Code"를 넣지 않습니다.**
4. 커밋 작성자 이메일은 GitHub noreply 주소입니다. 이미 전역 설정돼 있으니 바꾸지 않습니다.
5. 커밋 전과 푸시 전에 개인정보 검사를 돌립니다. 둘 다 통과해야 올립니다.
   ```
   PYTHONIOENCODING=utf-8 python ~/.claude/skills/git-privacy-guard/scripts/privacy_scan.py staged
   PYTHONIOENCODING=utf-8 python ~/.claude/skills/git-privacy-guard/scripts/privacy_scan.py range origin/master..HEAD
   ```
6. **커밋하지 않는 파일:** 루트의 `dl/`, `dl2/`~`dl6/`, `study-log/`, `summary.md`, 루트 `진행보고서/`, `문서/보고서/진행보고서/중간현황_9주차_발표자료_v2.pptx`. 사용자 소유이거나 일부러 빼 둔 파일입니다. `git add -A`를 쓰지 말고 파일을 하나씩 추가합니다.

## 4. 보안·개인정보 (공개 리포)

- `ask-campus/.env`에는 학교 계정과 API 키가 있습니다. **열어서 값을 출력하지 않고 커밋하지 않습니다.**

- 화면 캡처나 예시에 실제 학생 이름·학번·전화번호가 나오지 않게 합니다.
- 채점용으로 떼어 둔 Q&A 글 30개(`ask-campus/eval/holdout_qna.json`)는 읽거나 화면 예시로 쓰지 않습니다.

## 5. 서버 실행

GPU가 8GB라서 서버는 한 번에 하나만 띄웁니다. 모델 시험이나 학습을 할 때는 서버를 끕니다.

```bash
cd "/c/dev/Campus sLLM/ask-campus"
ASK_ADMIN_PASSWORD=<사용자에게 받은 값> PYTHONIOENCODING=utf-8 HF_HUB_OFFLINE=1 \
  .venv/Scripts/python.exe -m uvicorn src.server.app:app --host 0.0.0.0 --port 8000
```

- 모델을 올리는 데 30초 정도 걸립니다. `http://localhost:8000/api/v1/health`의 `model_ready`가 true가 되면 준비된 것입니다.
- **화면만 고칠 때:** 템플릿(HTML)은 서버를 다시 켜지 않아도 새로고침하면 바뀝니다. Python 파일을 고쳤으면 다시 켭니다.
- **외부 접속 (무료 터널):** 켤 때마다 주소가 바뀝니다. 서버를 외부에 여는 일이라 사용자가 원할 때만 켭니다.
  ```bash
  "/c/Program Files (x86)/cloudflared/cloudflared.exe" tunnel --no-autoupdate --url http://localhost:8000
  ```
  - 요청이 많으면 429로 거절됩니다. 1분 뒤 다시 시도하면 됩니다.
- **한글 요청 시험:** Git Bash의 curl로 한글 JSON을 보내면 깨집니다. Python으로 보냅니다.
- 실행 중인 서버가 있으면 새로 띄우기 전에 확인합니다. 포트가 겹치거나 GPU를 나눠 쓰면 답이 1~4분씩 걸립니다.

## 7. 학생 화면이 쓰는 API

### `POST /api/v1/ask`

요청:
```json
{"question": "2학기 기말고사 언제야", "campus": "아산", "department": null}
```
- `question`: 1~200자 (필수)
- `campus`: "영동" | "아산" | null
- `department`: 되묻기에서 고른 학과. 저장하지 않고 이번 답에만 씁니다.
- `test`, `exclude`: 평가 스크립트 전용입니다. 화면에서는 보내지 않습니다.

응답 (실제 예시, 11/24):
```json
{"answer_type": "문서",
 "answer": "제 2학기 기말고사는 2026년 12월 8일부터 12월 14일까지입니다.",
 "sources": [{"title": "학사일정: 제 2학기 기말고사", "kind": "공지",
              "source_url": "https://www.u1.ac.kr/u1/academic/academic-calendar.do",
              "menu_path": "홈 > 학사안내 > 학사일정", "collected_at": "2026-11-19T23:54:08+09:00"}],
 "schedule": null, "clarify": null, "pending_registered": false, "elapsed_ms": 171, "log_id": 2125}
```

되묻기 응답:
```json
{"answer_type": "되묻기", "answer": "장학금에 대해 무엇이 궁금한가요? ...",
 "clarify": {"field": "refine", "question": "...",
             "options": ["장학금 신청 기간", "장학금 신청 자격", "장학금 종류", "장학금 지급 금액"]}, ...}
```
- `clarify.field`는 둘 중 하나입니다.
  - `"refine"`: 고른 선택지를 새 질문으로 보냅니다.
  - `"department"`: 고른 학과를 `department`에 넣고 원래 질문을 다시 보냅니다. `more`가 있으면 '전체 보기'를 눌렀을 때 그 목록을 펼칩니다.
- `answer_type` 값은 `문서`, `FAQ`, `근거없음`, `되묻기` 네 가지입니다. 통학버스·학식처럼 코드가 계산한 답도 `문서`로 옵니다.
- `answer`에는 줄바꿈이 들어 있습니다. 통학버스 답은 답과 '기준 시간표' 사이에 빈 줄이 있습니다 (사용자 요청).
- `log_id`는 피드백을 보낼 때 씁니다.
- 오류 응답: 400 `INVALID_QUESTION`, 429 `RATE_LIMITED` (주소별 분당 20회). 둘 다 `message`를 그대로 보여 주면 됩니다.

### `POST /api/v1/feedback`
```json
{"log_id": 2125, "comment": "날짜가 틀려요"}
```
`comment`는 선택이고 300자까지입니다. 같은 답은 한 번만 저장됩니다.

### 그 밖
- `GET /api/v1/health`: `{"status", "model_ready", "data_updated_at"}`
- `GET /api/v1/faqs/{faq_id}`: FAQ 상세. `source_label`은 "관리자 등록 답변 · 날짜"입니다.

## 8. 설계 문서와 지금 구현의 차이 (화면에 영향 있는 것)

설계 문서(화면설계서 v1.5)는 아직 고치지 않았습니다. 화면을 설계대로 만들기 전에 아래 차이를 확인합니다.

| 항목 | 화면설계서 | 지금 |
|---|---|---|
| 모르는 질문 | "조교에게 전달됨" 안내, 답변 알림 | **조교 흐름 없음.** "해당 정보를 찾을 수 없습니다. 학교 홈페이지나 담당 부서에 문의해 주세요" + 담당 부서 안내 (11/21 결정) |
| 관리 웹 메뉴 | 답변 대기, FAQ, 문서, 중간 관리자, 요약 메일 | 6.2절 표의 메뉴. 중간 관리자·요약 메일·이메일 로그인은 미구현 |
| 학생 화면 | Android 앱 | Android 앱 + 시험용 웹 채팅 |
| 되묻기 (SCR-001a) | 설계만 있음 | 구현됨 (선택지 버튼) |
| 추천 질문, 마감 일정(SCR-005), 설정·첫 실행(SCR-004) | 설계 있음 | **미구현.** 프론트에서 새로 만들 후보 |
| 대화 기록 (FR-008) | 휴대폰에만 저장 | 미구현 |

화면설계서 그림은 `문서/그림/화면설계서/`에 있습니다 (`wire_scr001_main.png` 등). 설계 문서 자체(PPTX)는 직접 고치지 않습니다. `문서/작업/화면설계서/`의 생성 스크립트를 고쳐 다시 빌드하는 방식이고, 사용자가 요청할 때만 합니다.
