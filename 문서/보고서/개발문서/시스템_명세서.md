# 물어봐 캠퍼스 시스템 명세서 (프로토타입)

- 기준일: 2026-11-18
- 대상: 현재 `ask-campus/` 코드로 동작하는 서버, 웹 채팅 화면, 관리 웹
- 설계 문서(요구사항 정의서 v1.11, API 명세서 v1.0)와 다른 점은 맨 끝 [설계 문서와 다른 점](#9-설계-문서와-다른-점)에 모았습니다.

## 1. 개요

학생이 학교 생활에 대해 물으면, 학교 홈페이지에서 모은 자료에서 근거를 찾아 sLLM이 답합니다. 자료에 없는 질문은 관리 웹 '답변 대기'에 쌓이고, 관리자가 답을 등록하면 같은 질문부터 바로 그 답을 씁니다 (2026-11-21: 조교에게 넘기는 흐름은 없앰).

```
학생 질문 ─▶ FAQ(관리자 답변) 일치? ─예─▶ FAQ 답변
                 │아니오
                 ▼
          KURE-v1 임베딩 → Chroma 검색 → 순서 조정
                 │
     ┌───────────┼──────────────────────┐
     ▼           ▼                      ▼
  근거 없음   통학버스 시간표 질문      일반 질문
     │        → 코드가 시간 계산        → A.X 4.0 Light가 근거 3건으로 답변
     ▼                                   │ "찾을 수 없습니다"면 근거 없음
  답변 대기 등록 → 관리자 답변 → FAQ 즉시 반영
```

## 2. 구성 요소

| 구성 | 기술 | 위치 |
|---|---|---|
| 답변 모델 (sLLM) | `skt/A.X-4.0-Light` 7B, bitsandbytes 4bit, GPU 약 5~6GB | `src/server/llm.py` |
| 임베딩 모델 | `nlpai-lab/KURE-v1` fp16 | `src/server/index.py` |
| 벡터 DB | Chroma (컬렉션 `chunks`) | `data/chroma/` |
| 관계형 DB | SQLite | `data/askcampus.db` |
| 서버 | FastAPI + uvicorn | `src/server/app.py` |
| 수집기 | requests + BeautifulSoup | `src/ingest/` |
| 웹 채팅 화면 (시험용) | HTML + JS, `/api/v1/ask` 호출 | `src/server/templates/chat.html` |
| Android 앱 | Kotlin | `android/` |
| 실행 환경 | Python 3.12, torch 2.11 + CUDA 12.8, transformers 4.57.6, RTX 5060 8GB | `requirements.txt` |

## 3. 데이터 수집

모든 수집기는 요청 사이에 1초씩 쉽니다.

| 수집기 | 대상 | 출력 | 로그인 |
|---|---|---|---|
| `python -m src.ingest.run` | 학사일정, 통학버스 4쪽, 동아리현황, 학사·일반·장학 공지(게시판마다 최근 2쪽) | `data/chunks.jsonl` | 필요 없음 |
| `python -m src.ingest.run_login` | 커뮤니티 FAQ 전체, Q&A 중 2021년 이후 답변이 달린 글 | `data/chunks_login.jsonl` | 필요 |
| `python -m src.ingest.run_site` | 메인 사이트 메뉴 118개, 학과·대학원 사이트 31곳 (게시판은 2025-03-01 이후 글) | `data/chunks_site.jsonl` | 있으면 사용 |
| `python -m src.server.build_index` | 위 세 파일을 합쳐 SQLite `chunk` 테이블과 Chroma에 색인 | `data/` | - |

**로그인 계정**
- `ask-campus/.env`의 `U1_ID`, `U1_PW`에서 읽습니다.
- `.env`는 git에 올라가지 않습니다. 예시 파일은 `.env.example`입니다.

**개인정보 처리**
- Q&A 작성자 이름은 저장하지 않습니다. 본문에 그 이름이 나오면 '○○○'로 가립니다.
- 학생이 쓰는 게시판(Q&A, 자유게시판 류)은 전화번호, 학번, 이메일을 '***'로 가립니다.
- 학교가 올린 안내의 부서 전화번호와 교수 연락처는 공개 안내라 그대로 둡니다.
- 로그인 수집과 사이트 전체 수집은 원본 HTML을 디스크에 남기지 않습니다.
- 답변 대기 질문과 질문 기록도 전화번호·학번 형태를 가린 뒤 저장합니다.

**청크 형식** (`src/ingest/schema.py`)

| 필드 | 설명 |
|---|---|
| `chunk_id` | 주소와 순번으로 만든 해시 16자 |
| `category` | 학사정보, 통학버스, 동아리·행사, FAQ, Q&A, 학과, 대학생활, 공지, 대학행정, 대학소개 등 |
| `title` | 화면에 출처로 보여줄 제목 |
| `content` | 첫 줄은 `[출처] 제목 (게시일)` 머리말, 그 아래 본문. 최대 약 1,000자 |
| `source_url` | 원문 주소 |
| `metadata` | `campus`(아산·영동·공통), `posted_at`, `menu_path` |

## 4. 질문 처리 규칙 (`src/server/rag.py`)

1. **FAQ 우선**: 관리자가 등록한 FAQ와 유사도가 0.75 이상이면 그 답을 그대로 돌려줍니다.
2. **검색**: 캠퍼스 필터(선택한 캠퍼스와 '공통')를 걸고, 공식 자료와 Q&A를 따로 찾습니다. 점수 0.55 미만은 버립니다.
3. **순서 조정** (`_rerank`)
   - 질문에 '대학원'이 없으면 대학원 자료를 뺍니다.
   - 날짜를 묻는 질문('언제', '기간', '일정' 등)이면 순서를 조정합니다.
     - 오늘 이후 날짜가 있는 자료는 +0.03점을 줍니다.
     - 반년 넘게 지난 날짜뿐인 자료는 -0.08점을 줍니다.
4. **sLLM에 넘기는 근거**: 공식 자료 2건과 Q&A 1건, 모두 3건입니다. 공식 자료는 공지, 학사일정, 통학버스, 동아리, FAQ, 사이트 페이지예요.
5. **통학버스**
   - 질문에 정류장 이름이 있으면 sLLM을 쓰지 않고 코드가 시간표에서 시간을 고릅니다.
     - 줄임말도 알아봅니다: 두정 → 두정역, 터미널 → 천안터미널, 롯데 → 롯데마트, 삼일 → 삼일아파트.
   - 답의 종류는 '가장 빠른·다음 차', '첫차', '막차', '전체 시간'이에요.
     - 주말이나 방학 표는 질문과 오늘 요일을 보고 고릅니다.
   - 답에는 현재 시각을 쓰지 않고, 답과 '기준 시간표' 사이에 빈 줄을 둡니다.
6. **sLLM 답변**
   - 생성 설정: greedy, 최대 200토큰.
   - 답이 '찾을 수 없습니다' 류(`llm.is_not_found`)이면 근거 없음으로 바꿉니다.
7. **근거 없음**
   - 답변 대기에 등록합니다.
   - 비슷한 질문(0.85 이상)은 새로 만들지 않고 '같은 질문 수'만 올립니다.
   - 대기 질문은 30일 뒤 만료됩니다.

**sLLM 시스템 프롬프트 규칙** (`llm.SYSTEM`)
1. [자료]에 적힌 내용만으로 답합니다.
2. 답할 수 없으면 "해당 정보를 찾을 수 없습니다."라고만 답합니다.
3. 날짜, 시간, 금액, 장소는 자료 그대로 씁니다.
4. 존댓말로 1~4문장 답하고, 맺음말은 쓰지 않습니다.
5. 현재 시각을 기준으로 '오늘', '다음' 같은 말을 판단합니다.
6. 시간표 질문은 지금 이후 가장 가까운 시간으로 답합니다.
7. 학생 Q&A가 공지와 다르면 공지를 따르고, 개인 사정에 대한 답은 일반 안내로 쓰지 않습니다.
8. 같은 행사가 여러 해 있으면 지금 이후 가장 가까운 일정으로 답합니다.

**답변 정리** (`llm._clean`)
- 다음은 지웁니다.
  - HTML 태그
  - 자료 형식을 따라 쓴 줄('[자료]', '■')
  - 빈 항목('연락처: 010-')과 번호 앞자리만 남은 것('010--')
  - 40자 이하의 맺음말
- 실제 전화번호, 시간, 날짜는 지우지 않습니다.

## 5. API

| 메서드 | 경로 | 설명 |
|---|---|---|
| GET | `/` | 시험용 웹 채팅 화면 |
| GET | `/api/v1/health` | 서버 상태. `{"status", "model_ready", "data_updated_at"}` |
| POST | `/api/v1/ask` | 질문하기 |
| GET | `/api/v1/faqs/{faq_id}` | FAQ 한 건 |
| GET | `/admin/login`, POST `/admin/login`, POST `/admin/logout` | 관리 웹 로그인 (임시 비밀번호 `ASK_ADMIN_PASSWORD`) |
| GET | `/admin` | 답변 대기 목록 |
| GET | `/admin/pending/{id}` | 답변 작성 화면 |
| POST | `/admin/pending/{id}/answer` | 답변 등록 → FAQ 즉시 반영 |
| POST | `/admin/pending/{id}/not-mine` | 담당 아님 처리 |
| GET | `/admin/faqs` | FAQ 목록 |

**POST /api/v1/ask**

요청
```json
{"question": "두정에서 가장빠른 통학버스 알려줘", "campus": "아산", "category": null}
```

- `question`: 1~200자
- `campus`: 아산 또는 영동. 비우면 전체에서 찾아요.
- `category`: 비워 둡니다. 화면에 메뉴 구분을 두지 않기로 했어요.

응답
```json
{
  "answer_type": "문서",
  "answer": "두정역에서 가장 빠른 등교 버스는 08:00 (2회차, 2호차)입니다. …",
  "sources": [{"title": "…", "kind": "…", "source_url": "https://…", "menu_path": "…", "collected_at": "…", "label": "…"}],
  "schedule": null, "clarify": null,
  "pending_registered": false,
  "elapsed_ms": 1691
}
```

- `answer_type`
  - `문서`: 수집 자료로 답함
  - `FAQ`: 관리자 등록 답변
  - `근거없음`: 자료에서 답을 찾지 못함. 이때 답변 대기에 등록돼요.

오류

| 상태 | 코드 | 경우 |
|---|---|---|
| 400 | `INVALID_QUESTION` | 질문이 비었거나 200자를 넘음 |
| 429 | `RATE_LIMITED` | 같은 주소에서 분당 20회를 넘음 |
| 404 | `NOT_FOUND` | 없는 FAQ |

## 6. DB (SQLite)

| 테이블 | 용도 | 주요 칼럼 |
|---|---|---|
| `chunk` | 수집 자료 원문 | chunk_id, category, campus, title, content, source_url, menu_path, posted_at |
| `pending_question` | 답변 대기 질문 | pending_id, question(가림 처리), campus, question_count, status(대기·답변완료·담당아님), expires_at, vec |
| `faq` | 관리자 등록 답변 | faq_id, pending_id, question, answer, category, campus, ask_count, vec |
| `query_log` | 질문 기록 | question(가림 처리), campus, answer_type, response_ms, created_at |

## 7. 설정 (환경 변수)

| 이름 | 기본값 | 설명 |
|---|---|---|
| `ASK_LLM_MODEL` | `skt/A.X-4.0-Light` | 답변 모델 |
| `ASK_LLM_QUANT` | `4bit` | `4bit`, `8bit`. 비우면 bf16 (GPU 16GB 이상) |
| `ASK_LLM_ADAPTER` | (없음) | LoRA 어댑터 경로나 Hugging Face ID |
| `ASK_EMBED_MODEL` | `nlpai-lab/KURE-v1` | 임베딩 모델 |
| `ASK_EMBED_DEVICE` | `cuda` | `cpu`로 하면 KURE를 CPU에서 돌림 |
| `ASK_USE_LLM` | `1` | `0`이면 sLLM 없이 근거 문장만 돌려줌 |
| `ASK_MIN_SCORE` | `0.55` | 근거로 쓸 최소 검색 점수 |
| `ASK_FAQ_SCORE` | `0.75` | FAQ 답을 그대로 쓸 유사도 |
| `ASK_SAME_QUESTION` | `0.85` | 답변 대기에서 같은 질문으로 묶는 유사도 |
| `ASK_ADMIN_PASSWORD` | (없음) | 관리 웹 임시 비밀번호. 없으면 로그인 불가 |
| `ASK_SECRET` | 개발용 값 | 관리 웹 쿠키 서명 키. 실제 운영 때 바꿈 |

## 8. 성능 (2026-11-18 기준)

| 종류 | 문항 수 | 설명 |
|---|---|---|
| answer | 84 | 자료에 답이 있는 질문. 그중 75문항은 정답 문자열로 자동 채점 |
| none | 16 | 자료에 답이 없는 질문 |

| 지표 | 결과 |
|---|---|
| 정답 (자동 채점 75문항) | 69 |
| 자료에 없는 질문 거르기 | 12/16 |
| 통학버스 시간표 시험 (`scripts/time_test.py`) | 12/12 |
| sLLM 평균 생성 시간 | 약 3초 (긴 목록 답변은 10~20초) |
| GPU 메모리 최대 | 약 7.2GB (KURE + A.X 4bit) |

**재현**: 서버를 끄고 `ask-campus` 폴더에서 실행합니다.
```
.venv\Scripts\python scripts\model_compare.py 결과.json --eval
.venv\Scripts\python scripts\time_test.py
```

**알려진 오답**
- 같은 행사가 여러 해 있으면 지난 해 날짜로 답할 때가 있습니다 (학위수여식).
- 비슷한 항목의 숫자를 가져다 붙입니다.
  - 시내버스 요금을 통학버스 요금처럼 답함
  - 다른 장학금 기준을 성적장학금 기준처럼 답함
  - 다른 자격증 지원 프로그램을 토익 응시료 지원처럼 답함
- 자료가 많아지며 정답 자료가 비슷한 학과 페이지에 밀립니다 (조기졸업 문의 전화번호, 형제 장학금).

## 9. 설계 문서와 다른 점

| 항목 | 설계 문서 | 현재 구현 | 이유 |
|---|---|---|---|
| 답변 모델 | Kanana 1.5 2.1B | A.X 4.0 Light 7B 4bit | 13개 모델 비교에서 정확도·속도 최상 (`문서/보고서/개발문서/sLLM_모델비교.md`) |

| 화면 | SCR-001에 카테고리 칩 4개 | 입력창 하나 | 다른 LLM 채팅처럼 단순하게. UI는 Figma로 다시 설계 예정 |
| 웹 채팅 화면 | 없음 | `/` 시험용 화면 | 앱 없이 브라우저로 시험하기 위해 |
| 첨부파일 | 본문 추출 예정 | 파일 이름만 | 아직 구현 안 함 |
