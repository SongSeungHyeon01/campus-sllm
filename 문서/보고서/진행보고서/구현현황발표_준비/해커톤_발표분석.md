# 해커톤 발표 분석 & 인수인계서

> 자료: 여행 서비스 해커톤(하나투어 주관으로 추정) 전반부 10팀 발표 녹취록 (약 1시간 31분)
> 목적: (1) 발표가 어떻게 진행됐고 무엇이 평가받았는지 파악 → (2) 내 프로젝트 발표에 적용 → (3) VS Code에서 작업 중인 발표 파일에 접목
> 주의: 녹취는 음성인식(STT) 결과라 팀명·서비스명·숫자 일부가 깨져 있음. 9~10번 팀 구간은 발표 본문 일부가 빠져 있고 Q&A가 섞여 있음.

---

## 1. 행사 진행 방식 (포맷)

| 단계 | 내용 | 시간 |
|---|---|---|
| ① 호명 | 사회자가 팀명 호명 → 발표자 무대 앞으로 | 약 10초 |
| ② 응원 구호 | 사회자 "하나" → 청중 "투어" (긴장 완화용 구호) | 약 10초 |
| ③ 발표 | 슬라이드 + 시연 영상(대부분 녹화 영상) | **약 5~7분** |
| ④ 질의응답 | 심사위원 3~4명이 1개씩 질문 | **약 3~4분**, 사회자가 시간 되면 끊음 |
| ⑤ 종료 | "OO팀에 큰 박수" → 다음 팀 | — |

- 한 팀당 슬롯 ≈ **10분** (발표 6~7분 + Q&A 3~4분)
- 전반부 10팀 → 10분 휴식 → 후반부 (총 20팀)
- 시연은 **녹화 영상**이 표준. 라이브 데모 대신 "영상 틀어주세요 / 몇 분 몇 초로 넘겨주세요"를 운영진에 요청하는 방식 → 영상 타임스탬프를 미리 정리해둘 것
- Q&A는 시간 초과 시 답변 중간에도 끊김 → **답변은 30초 이내, 결론 먼저**

## 2. 공통 발표 구조 (잘한 팀들의 뼈대)

거의 모든 팀이 아래 흐름을 따랐고, 평가가 좋았던 팀일수록 순서가 분명했음.

1. **공감 훅 (15~30초)** — "한 번쯤 이런 경험 해보셨죠?" / "여행 가고 싶다, 근데 가기 싫다" 같은 질문형 도입
2. **문제 정의 + 숫자 근거** — 자체 설문(32명, 70명, 182명 등) + 외부 통계(Citi·Harris Poll 45%/82%, 싱가포르 조사 53%/49%, 업계 리더 34%)
3. **원인 분석** — "왜 이 문제가 생기나?"를 한 줄로 정의 (예: "누가 뭘 먹었는지는 각자만 아는데, 입력은 총무 한 명이 한다")
4. **기존 서비스 한계 / 경쟁사 비교** — 비교표로 "우리만 다 된다"
5. **해결책 = 사용자 시나리오 기반 시연** — 상황 가정("해외 식당에 들어가면 제일 먼저 뭘 하죠?") → 기능 시연
6. **AI를 왜 쓰는지 + 틀리면 어떻게 막는지** — 이 대회의 핵심 평가 축
   - "규칙으로는 안 되고 AI가 맥락을 읽어야 해서" → 필요성
   - 단계형 검증 파이프라인: 촬영/압축 → LLM 추출 → 코드로 형식·합계 검사 → 사람이 최종 확인
   - 단가 제시: 영수증 1장 4.3원 / 20원, 관광지 1곳 채점 100~200원
7. **타깃·시장 규모** — 2030 / 친구·연인 동행 / 효도여행 자녀 등
8. **BM** — 제휴 수수료, 여행 단위 패스, B2B(여행사 탑재)
9. **실현 가능성** — "오늘 보여드린 기능은 전부 실제로 동작합니다" + 예외 케이스 검증 사례
10. **슬로건 마무리** — "돈 걱정 없는 여행은 ○○와 함께", "일도 공정하게, 돈도 공정하게"

## 4. 심사위원 질문 패턴 분석

심사위원은 성향이 뚜렷하게 나뉨. 내 발표에 미리 답을 박아둘 것.

### 심사위원 A (P2) — 실무·운영 관점
- 예외 상황: "카드 안 되면 현금은?", "항공권 없으면 못 쓰나?", "로밍 끄면 알림 못 받잖아"
- 데이터 수집: "전 세계 식당 데이터를 어떻게?"
- **개인정보·보안**: "여권 OCR 보안 때문에 우리 회사도 애먹는다"
- 사업 연동 계획: "6개월 내 연동, 구체적으로?"
- 비용 부담 주체: "여행사가 왜 돈을 낸다고 생각?"

### 심사위원 B (P3) — 기술·데이터 관점
- 저장 구조: "로컬? 서버? 어떻게 관리?"
- AI 비용 관리: "모델에 따라 비용 달라지는데?"
- **데이터 출처와 신뢰성**: "DB 어디서? 그 신뢰도가 후속 정확도를 좌우"
- 실측 여부: "내부 OCR 실제로 확인했나, 그냥 쓰겠다는 건가?"
- 가격 형평성: "짧게 가는 사람은 손해 아닌가"

### 심사위원 C (P4) — 비즈니스 관점
- "BM이 뭐죠?", "첫 고객 어떻게 유치?", "ChatGPT 두고 이걸 왜 써요?", "실제로 시연(테스트)해 봤나?"

### 심사위원 D (P5) — 핵심 평가자 (가장 날카로움, 매 팀 질문)
- **시장 규모 논리**: TAM 숫자가 아니라 "1인당 수익 × 사용자"로 도출돼야 함
- **지불 의사**: "영수증 계산기에 돈 내는 거 본 적 있나?"
- **차별성의 근거**: "AI 모델이 아니라 **우리가 무엇을 했기 때문에** 정확도가 높은지"
- **실현 가능성 = 땀 냄새**: "앱을 만들었으니 실현 가능하다가 아니라, 데이터 차이를 어떻게 인지·구분하는지 직접 파봤는가"
- 실시간성: "추천했는데 막상 가보니 웨이팅" → 실시간 데이터 확보 방안
- 가치 훼손: 단점만 점수화하면 여행 설렘이 사라짐
- UX/디지털 리터러시: 정보를 모은다고 부모님이 쓸 수 있는 게 아님
- 확장 전략 일관성: 큰 시장 → 작은 시장 확장은 역행
- 칭찬 포인트: "문제 인사이트를 **총무의 노동**으로 찍어낸 것은 의미 있다", "국내 특수 상황에 집중해서 좋았다", "직접 겪어봐서 공감"

## 5. 점수를 얻은 것 vs 잃은 것

### ✅ 얻은 것
- 한 문장으로 꽂히는 **문제 재정의** (하실: "총무의 노동")
- **자체 실측치** (정확도 165/167, 근거 523건, 1장 4.3원)
- 단계형 **AI 검증 파이프라인 + 사람 최종 승인**
- **한계를 먼저 공개**하고 개선 계획 제시 (반걸음)
- 구체적 인물·장면으로 시작하는 시연 ("술 안 마신 지음이는 9,773원 손해")
- "오늘 보여드린 기능은 전부 실제 동작"

### ❌ 잃은 것
- 시장 규모 숫자를 BM과 연결 못 함 (1번 팀 즉시 인정)
- "DB를 사겠다 / 크롤링하겠다 / 아직 구현 못 했다" — 핵심 데이터 확보가 미정
- "ChatGPT로 되잖아"에 대한 답이 "모델 선택" 수준
- BM을 "고민 중"이라고 말함
- 개인정보 질문에 "딱히 문제없을 것 같다"
- 질문 의도를 못 알아듣고 되묻기 → 시간 소모
- 확장 전략이 타깃과 역방향

## 6. 내 발표 적용 체크리스트

### 6-1. 구성 (6~7분 기준 권장 배분)
| 구간 | 시간 | 들어갈 것 |
|---|---|---|
| 훅 | 0:00–0:30 | 청중 경험 질문 1개 |
| 문제 | 0:30–1:30 | 문제 한 문장 재정의 + 숫자 2개(자체 설문 1, 외부 통계 1) |
| 원인 | 1:30–2:00 | "왜 기존 방식으론 안 되나" 한 줄 |
| 해결/시연 | 2:00–4:30 | 장면 기반 시연 영상 (타임스탬프 메모) |
| AI·검증 | 4:30–5:15 | 왜 AI인가 / 틀리면 어떻게 막나 / 1회 단가 |
| 시장·BM | 5:15–6:15 | 타깃 → 1인당 수익 → 목표 사용자 → 매출 (숫자 연결) |
| 마무리 | 6:15–6:45 | 한계 1줄 + 슬로건 |

### 6-2. 반드시 슬라이드/대본에 넣을 것
- [ ] 문제를 한 문장으로 재정의한 **키 카피**
- [ ] 자체 실측치 최소 1개 (정확도, 테스트 건수, 처리 시간 등)
- [ ] **"ChatGPT로 하면 되잖아?"에 대한 답** — 우리만의 데이터/워크플로/검증 단계
- [ ] AI 사용 위치 + 검증 단계 + 사람 확인 지점 다이어그램
- [ ] 1회 AI 비용 (원 단위)
- [ ] 데이터 출처와 신뢰성, 미확보 시 확보 계획(구체적 소스)
- [ ] 개인정보 처리 방침 한 줄 (저장 안 함 / 어디서 처리 / 삭제 시점)
- [ ] BM: 누가, 왜, 얼마를 내는지 + 시장규모와 숫자로 연결
- [ ] 첫 고객 100명 확보 경로 (구체적 채널)
- [ ] 한계와 다음 단계

## 7. 인수인계 (VS Code 작업 파일에 접목하기)

### 7-1. 현재 상태
- 완료: 녹취록 분석, 발표 구조·심사 패턴 정리, 적용 체크리스트 작성 (이 문서)
- 미완료: 실제 발표 파일(VS Code에서 작업 중인 파일)에 반영 — **해당 파일 경로·형식을 아직 받지 못함**

### 7-2. 다음 작업자(또는 다음 Claude 세션)가 할 일
1. 작업 중인 발표 파일 확인 (예상 형식: HTML 슬라이드 / Markdown 대본 / PPT 원고 중 하나)
2. 기존 슬라이드 순서를 **섹션 6-1 구성표**에 매핑 → 빠진 구간 표시
3. **6-2 체크리스트** 항목별로 현재 파일에 있는지 O/X 표 작성 → 없는 것 추가
4. **6-3 답변 카드**를 프로젝트 내용으로 채워 `QnA_대비.md`로 별도 저장
5. 시연 영상이 있으면 구간 타임스탬프 표 작성
6. 시간 리허설: 대본 글자 수 기준 분당 약 300~350자로 6~7분 맞추기

### 7-3. 다음 세션에 그대로 붙여넣을 지시문
