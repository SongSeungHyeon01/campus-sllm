## 3. 요구사항 정의서 (v1.6)

### 3.1 과제 배경과 목적

- **문제:** 학사일정·통학버스·동아리·공모전 정보가 학교 홈페이지, 학과 공지, 에브리타임 등에 흩어져 있습니다. 포털 검색은 정확한 키워드가 필요하고 메뉴가 복잡합니다. 학생이 스스로 찾지 못한 같은 질문은 학과 사무실로 반복해서 몰립니다.
- **목적:** RAG(검색 증강 생성)와 파인튜닝한 sLLM을 결합해, 캠퍼스 정보를 자연어로 묻고 근거가 있는 답을 바로 받게 합니다.
  1. 정보 통합: 흩어진 정보를 하나의 질의응답 창구로 모읍니다.
  2. 정확한 실시간 응답: 시간표·일정이 바뀌어도 자료만 다시 수집하면 됩니다.
  3. 경량 AI: 1차는 서버에서 구동하고, 확장 단계에서 스마트폰 온디바이스 시연을 합니다.
- **범위 밖:** 학사정보센터 연동, 개인 시간표·성적 같은 로그인이 필요한 개인화 정보, 로그인이 필요한 학교 FAQ 자동 수집

### 3.2 사전 설문과 페르소나

2026년 9월 15~16일 구글폼으로 재학생 사전 설문을 했습니다(응답 9건).

| 문항 | 결과 | 요구사항 반영 |
|---|---|---|
| 포털 이용 시 불편한 점 | 검색 기능 부실 44%, 복잡한 메뉴 33% (합계 78%) | 자연어 질의(FR-001~003), 메뉴 위치 안내(FR-022) |
| 가장 도움이 될 정보 | 대외활동·공모전 33%, 학사정보 33%, 동아리·행사 22%, 통학버스 11% | 교외활동·학사정보 우선(FR-011, 013), 마감 일정(FR-020) |
| 캠퍼스 AI 사용 의향 | 긍정 89% (8/9) | 개발 필요성 근거 |
| 우려 사항 | 개인정보 유출 2명, 오해로 오히려 오래 걸릴까 1명 | 익명 이용(2.6), 근거 없음 응답(FR-005), 응답 시간(PER-001) |

응답자가 모두 아산캠퍼스이고, 학과를 적은 응답자는 모두 AI소프트웨어학과입니다. 학교 전체 의견으로 보기에는 표본이 작고 치우쳐 있어서, 방향을 잡는 참고 자료로만 썼습니다.

| 대표 페르소나 | 핵심 불편 | 관련 요구사항 |
|---|---|---|
| 공모전을 매주 찾는 아산캠퍼스 AI소프트웨어학과 3학년 | 공고가 여러 곳에 흩어져 있고 마감을 놓치기 쉬움 | FR-013, 020, 021 |
| 학사 공지를 놓치지 않으려는 편입생 | 키워드를 모르면 검색이 안 되고, 핵심 내용이 첨부파일에 묻힘 | FR-002, 011, 014, 021 |
| 동아리·행사를 알아보는 아산캠퍼스 신입생 | 어느 메뉴에 무슨 정보가 있는지 모르고, 영동캠퍼스 정보와 헷갈림 | FR-012, 022, 023, 026 |
| 반복 문의에 답하는 학과 조교 | 같은 질문에 반복 응대, 공식 답변을 알릴 방법이 없음 | FR-025, 028~030 |

| 〃 | FR-025 답변 대기·인기 질문 통계 | 중 |

**조교 답변 흐름 (FR-028~030):**
1. 근거를 찾지 못하면 "해당 정보를 찾을 수 없습니다" 아래에 "학과 조교에게 물어볼까요?" 버튼을 보여줍니다.
2. 학생이 누르면 질문 문장, 카테고리, 캠퍼스, 익명 기기 토큰만 저장합니다. 비슷한 질문은 기존 요청에 묶습니다.
3. 조교가 웹에서 답변을 쓰면 승인 없이 바로 FAQ DB에 저장하고 다시 색인합니다. 이후 같은 질문의 근거가 됩니다.
4. 요청한 모든 기기에 FCM 익명 알림을 보내고 토큰을 지웁니다. 답이 없는 요청은 30일 뒤 만료됩니다.

### 3.5 비기능 요구사항

| ID | 항목 | 기준 |
|---|---|---|
| PER-001 | 답변 응답 시간 | 평균 5초 이내 |
| PER-002 | 문서 검색 시간 | 임베딩 + 벡터 검색 1초 이내 (청크 1만 개 이하) |
| PER-003 | 검색 정확도 | 테스트 질문 80개 중 정답 근거가 상위 3개 안에 드는 비율 80% 이상 |
| PER-004 | 모델 경량화 | 파라미터 10억 개 이하 또는 4bit 기준 메모리 4GB 이하 |
| PER-005 | 데이터 갱신 | 전체 수집부터 재적재까지 30분 이내 |
| PER-006 | 동시 처리 | 시연 환경에서 동시 요청 10건 오류 없이 처리 |
| PER-007 | 앱 구동 | 메인 화면 표시까지 3초 이내 |
| PER-008 | 공지 반영 | 게시 후 3시간 이내 반영 |
| PER-009 | 마감 일정 조회 | 목록 표시 2초 이내 |
| PER-010 | 조교 답변 반영 (v1.5 추가) | 등록 후 1분 이내 재색인·알림 발송 |

- **가용성:**
  - 공지·교외활동은 3시간마다, 그 밖의 소스는 매일 03:00에 수집합니다.
  - 서버가 10초 넘게 응답하지 않으면 재시도 버튼을 보여주고, 수집에 실패하면 직전 데이터를 유지합니다.
  - 마감 알림은 기기 안에서 예약하므로 서버가 꺼져도 동작합니다.
  - 답변 요청은 30일 동안 보관합니다(AVL-001~008).
- **보안:**
  - 학생은 로그인 없이 익명으로 쓰고, 이름·학번 같은 개인정보는 받지 않습니다.
  - 관리 웹은 조교·관리자 계정으로만 들어갈 수 있습니다. 비밀번호는 해시로 저장하고, 5회 연속 실패하면 10분 동안 막습니다.
  - 조교와 관리자의 권한을 나눴습니다.
  - 질문은 200자까지 받고, 기기당 분당 20회로 제한합니다.

## 5. 모델 선정·개발 가능성·예산

### 5.1 추천 모델 조합 (팀 확정 전)

| 역할 | 1순위 | 비교·대안 | 선정 이유 |

| 온디바이스 시연 (확장) | EXAONE 4.0 1.2B (LG) | Qwen3.5 0.8B | 가장 작은 한국어 강세 모델. 비상업 라이선스(교육 목적 허용) |
| 임베딩 | KURE-v1 (고려대) | BAAI/bge-m3 | 한국어 검색 벤치마크 nDCG@10 0.7616, MIT, Chroma에 바로 사용 |
| 리랭커 (고도화) | bge-reranker-v2-m3-ko | 없이 시작 | 상위 3개 정확도(PER-003) 개선용, 기본 RAG 완성 후 추가 |
| 벡터 DB | Chroma | FAISS | 설치가 간단하고 메타데이터 필터 지원, 조교 답변 한 건만 다시 색인하기 쉬움 |

요구사항 정의서 v1.6의 FR-016·FR-017·2.7 기술 표에는 아직 예전 후보(BGE-m3/ko-sroberta, Gemma/Phi-3-mini)가 남아 있습니다. 팀에서 모델을 확정하면 함께 고칩니다. 최종 선택은 테스트 질문 80개로 비교해서 정합니다.
