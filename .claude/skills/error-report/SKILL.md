# 오류 원인 보고서 (error-report)

작업 중 만나는 모든 실제 오류/문제를 채팅에만 남기지 않고, **현재 작업 중인
프로젝트의 루트 폴더** 안에 md 파일로 영구 기록한다. 목적: 나중에 같은 문제를 다시
만났을 때(또는 팀원이 만났을 때) 원인·시도한 방법·최종 해결책을 바로 찾을 수 있게
하는 것. 이 스킬 자체는 전역(`~/.claude/skills/`)에 있지만, **기록은 항상 그 순간
작업 중인 프로젝트 폴더 안에** 남긴다 — 특정 프로젝트에 종속되지 않는다.

## 프로젝트 루트를 어떻게 정하나

- 현재 작업 중인 파일/명령이 속한 git 저장소 루트(`git rev-parse --show-toplevel`)를
  우선 사용한다.
- git 저장소가 아니면, 작업 중인 디렉토리 트리에서 가장 상위의 프로젝트성 폴더
  (package.json/requirements.txt/pyproject.toml 등이 있는 곳)를 프로젝트 루트로
  본다.
- 여러 프로젝트를 동시에 다루는 대화라면, 문제가 실제로 발생한 그 프로젝트의 루트에
  기록한다(다른 프로젝트 폴더에 잘못 남기지 않는다).

## 언제 기록하나

기록 대상 (하나라도 해당하면 기록):
- 프로그램/서버/빌드/테스트가 실제로 실패했다 (예외, 크래시, non-zero exit, 빌드 실패)
- 원인을 바로 알 수 없어서 조사가 필요했다 (로그 확인, 재현, 가설 검증 등)
- 겉보기엔 사소해 보였는데 원인이 비직관적이었다 (예: 인코딩 문제, 네트워크 어댑터
  설정, 라이선스 제약 등 코드만 봐서는 안 보이는 원인)
- 해결까지 여러 번 시도했거나(1차 시도 실패 → 2차 시도), 아직도 미해결 상태로 남았다

기록 제외 (기록하지 않아도 됨):
- 단순 오타, 사용자가 명령을 잘못 친 것 자체(단, 그로 인해 실제 시스템 문제가 드러났다면
  그 문제는 기록 대상)
- 이미 알려진 원인으로 즉시(추가 조사 없이) 고친 사소한 코드 실수

## 어디에, 어떻게 저장하나

- 폴더: `{프로젝트 루트}/docs/오류보고서/`
- 파일명: `YYYY-MM-DD_짧은-슬러그.md` (날짜는 발생 시점 기준, 슬러그는 영문 kebab-case
  로 문제를 한두 단어로 요약, 예: `2026-07-28_docker-tls-bad-record-mac.md`)
- 같은 문제를 다시 조사/재발했으면 새 파일을 만들지 말고 기존 파일에 "## 재발"
  섹션을 추가한다 (동일 이슈가 여러 파일로 흩어지는 것을 막기 위함).
- `{프로젝트 루트}/docs/오류보고서/INDEX.md`에 한 줄씩 추가:
  `- [YYYY-MM-DD] 제목 — 한 줄 요약 (상태) → 파일명` 최신이 위로 오도록 유지한다.
  INDEX.md가 없으면 새로 만든다.

## 보고서 템플릿

```markdown
# {제목 — 무엇이 문제였는지 한 문장}

- **발생 시각**: YYYY-MM-DD
- **위치**: {파일/명령/서비스}
- **상태**: 미해결 | 해결됨 | 우회함

## 증상
{무엇이 어떻게 잘못 동작했는지 — 실제 에러 메시지/로그 인용}

## 원인 조사
{시도한 가설과 검증 과정. 틀린 가설도 "이건 아니었다"로 남긴다 — 나중에 같은 삽질을
반복하지 않기 위함.}

## 근본 원인
{최종적으로 확인된 원인. 확인 안 됐으면 "미확인" + 가장 유력한 가설.}

## 해결 방법 / 다음 시도
{실제로 적용한 조치, 또는 다음에 시도할 것. 관리자 권한처럼 사용자 조치가 필요하면
명시한다.}

## 재발 방지
{같은 문제가 다시 안 생기게 하려면 뭘 바꿔야 하는지. 없으면 생략 가능.}
```

## 주의

- 문서·PRD·이전 요약이 아니라 **실제로 이번 세션에서 관찰한 사실**만 적는다
  (evidence-based-answers 스킬과 동일한 원칙 — 추측은 "가설"이라고 명시).
- 민감정보(비밀번호, API 키, 토큰)는 절대 그대로 적지 않는다.
- 문제가 해결된 뒤에도 보고서를 지우지 않는다 — "상태"만 해결됨으로 바꾸고 해결
  과정을 그대로 남긴다(다음에 비슷한 증상이 나왔을 때 검색될 수 있게).
